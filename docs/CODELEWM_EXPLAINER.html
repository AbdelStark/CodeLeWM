01 orientation

What it actually is, in one screen.

If you read nothing else, read this. The project framework compresses into four claims and one equation.

C1
Predicts latents, not tokens

It does not generate code. It learns to predict the 256-d latent representation of an after-state from the before-state and an action.

C2
Scorer and reranker

The downstream artifact is a local, trust-checkable scoring tool. It ranks candidate patches based on how well they match the expected transition.

C3
Energy-based ranking

Transitions are scored by L2 distance between the predicted latent and the candidate's encoded latent. Lower energy is better.

C4
Explicitly falsifiable

The model contains strict kill criteria. If embeddings collapse or the action signal is ignored, training halts with a diagnostic report.

transition energy $$ E(s_{\text{b}}, a, s_{\text{a}}) = || P(E_{\theta}(s_{\text{b}}), A_{\phi}(a)) - E_{\theta}(s_{\text{a}}) ||^2 $$
the contribution Validates whether a compact JEPA can learn action-conditioned structure over domains that violate continuity and smooth action manifolds. It measures representation quality through retrieval metrics rather than generation aesthetics.

04 ablation

Three ways to see an action.

Code edits have no natural continuous control vector. The dataset provides three strict views to ensure the model learns dynamics, not just textual overlap.

06 inference loop

The model as a planner.

An LLM proposes; the world model disposes. Given an optimization goal, candidate patches are encoded into latents and ranked by their distance to a predicted target — no code is run, no tokens are decoded.

01
LLM proposes

An external coding LLM (or any search procedure) emits N candidate patches for the same before-state and goal headline. Diversity matters more than perfection.

02
WM imagines

The predictor P(z_b, a_goal) emits a goal latent — what the after-state should look like in 256-d if the goal were achieved. This is the imagined consequence.

03
Argmin energy

Each candidate after-state is encoded and compared to the goal latent. The lowest-energy edit wins. Planning collapses to a nearest-neighbor lookup in semantic space.

def plan_edit(before, goal_text, n=8):
    # 1. ground state + intent in latent space
    z_b      = E(before)
    a        = ActionEncoder(goal_text)
    z_target = P(z_b, a)                # imagined consequence

    # 2. ask the proposer for diverse candidates
    candidates = llm.sample_patches(
        before, goal_text, n=n, temperature=0.9
    )

    # 3. score by latent proximity — never execute
    scored = []
    for patch in candidates:
        after = apply_patch(patch, before)   # parse only
        if not parses(after): continue
        z_a   = E(after)
        E_t   = ((z_target - z_a) ** 2).sum()
        scored.append((E_t, patch))

    return sorted(scored)[0]              # argmin energy
why this can work The encoder is trained to compress code into a representation that predicts action-conditioned transitions. To do that under SIGReg pressure, it has to abandon textual surface and surface high-level semantics: control flow, side-effect profile, error-handling discipline, API shape. Those are precisely the axes a planner needs.
multi-objective planning Because P emits full latents — not scalar rewards — multiple goal vectors can be evaluated in one pass. Maintainability, performance, defect-likelihood: each is a separate direction in the same 256-d manifold. The harness can Pareto-rank, weight, or constrain along any of them.
what this is not The world model does not generate patches. It does not execute them. It is a frozen, trust-checkable distance function — a learned judge over the discrete world of code edits.
07 honesty

Explicit falsification.

A model is useless if its failures are silent. CodeLeWM defines strict kill criteria and diagnostic bounds. If it fails these, training halts.

KILL-B
Action Insensitivity

If the model performs identically when the action is shuffled or replaced with zeros, it has collapsed to a prior. The text-action metric must beat the shuffled-action baseline by a strict margin.

KILL-C
Embedding Collapse

The system constantly computes the effective rank of the embeddings and nearest-neighbor entropy. If the effective rank ratio stays below 0.20 for two intervals, a KillReport is emitted.

KILL-E
Patch Surprise Failure

Retrieval against random code is easy. The model must score true patches lower (better) than plausible decoys (mutations, same-file wrong edits). Target AUC is > 0.70.

LEAK
Data Leakage

A 64-bit SimHash enforces strict deduplication. Repository-level splits ensure no functions from the same repo exist in both train and test pools.

08 reproduce

Run it yourself.

The entire pipeline is manifest-backed. Every step records checksums and provenance.

# Build deterministic context capsules
uv run codelewm dataset build \
  --config config/first_results/dataset_build.json \
  --out .artifacts/build

# Pack into HDF5 tensors
uv run codelewm dataset pack \
  --manifest .artifacts/build/manifest.json \
  --out .artifacts/pack
# Train the transition model
uv run codelewm train \
  --config config/train/codelewm_tiny.yaml \
  --executor torch \
  --device cuda \
  --out .artifacts/train
# Evaluate patch retrieval metrics
uv run codelewm eval retrieval \
  --checkpoint .artifacts/train/checkpoints/checkpoint.pt \
  --data .artifacts/pack \
  --out .artifacts/eval

# Verify lineage of all artifacts
uv run codelewm manifest verify \
  --manifest .artifacts/eval/manifest.json
# Score candidate patches without code execution
uv run codelewm eval scorer-quality \
  --config config/first_results/scorer_quality.json \
  --checkpoint .artifacts/train/checkpoints/checkpoint.pt \
  --out .artifacts/scorer
