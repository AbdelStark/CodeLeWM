01 The Big Picture

CodeLeWM is a latent world model for code. Given a piece of code (state_before) and an edit (action), the model predicts the latent representation of the resulting code (z_pred_after) and is trained to make that match the latent of the actual post-edit code (z_after). This is a JEPA-style objective — we never reconstruct pixels or tokens, only embeddings.

The defining risk
Latent predictors are prone to representation collapse — the model trivially wins by outputting a constant vector for everything, so z_pred_after == z_after always. Almost every “weird” piece of this codebase (SIGReg, action-swap diagnostics, the collapse smoke test, the validation distance gap) is a defense against collapse or a probe to detect it.

What the model actually computes

Hold these symbols in your head; they appear in every subsequent section:

SymbolDefinitionWhere it comes from
z_before Encoder applied to pre-edit code E(state_before)
z_after Encoder applied to post-edit code E(state_after)
action_emb Encoder applied to the edit A(action)
z_pred_after Transition head's prediction T(z_before, action_emb)

The training goal in one line:

Learn E, A, T such that   T(E(s), A(a)) ≈ E(s')  for every transition (s, a, s') in the data.

The naive thing — minimize ‖z_pred_after − z_after‖² — has a degenerate global optimum: make E constant. Everything else in this crash course exists to make collapse a worse minimizer than the actual task.

03 The Training Executor

File: codelewm/training/torch_executor.py:89. The function is large but follows a strict shape. Read it as five phases.

3.1  Setup phase

runtime = _require_torch_runtime()
_seed_everything(context.config.seed, runtime)
selected_device = _resolve_device(device or context.config.trainer.accelerator, runtime)
precision = _precision_dtype(context.config.trainer.precision, selected_device, runtime)
  • Torch is optional. The package imports with no torch installed; the guard fails loud if you try to train without the train dependency group.
  • Seed everything. Python random, NumPy, torch (CPU + CUDA). Same config + same seed ⇒ same trajectory.
  • Device resolution. auto prefers CUDA, then MPS, then CPU. Explicit cuda raises if unavailable — fail loud, not silent.
  • Precision dtype. bf16-mixed is the modern default on Ampere+. fp16 is forced to fp32 on CPU because fp16 on CPU is meaningless.

3.2  Data & model construction

train_dataset = PackedTransitionHdf5Dataset(train_path, action_view=..., vocab_size=...)
val_dataset   = PackedTransitionHdf5Dataset(val_path,   ..., allow_empty=True)

model = build_torch_transition_model(_model_config(context.config))
model.to(selected_device)
optimizer = runtime.optim.AdamW(model.parameters(), lr=..., weight_decay=...)

HDF5 packed format

Each split is one .h5 file containing three groups — state_before, state_after, and either action_text or action_abs. Fixed-width int matrices. Packing is offline so training does zero tokenization on the hot path.

action_view switch

text = raw diff/patch text. abstract = structured action. patch is diagnostic only and explicitly raises in the dataset constructor — a hard contract.

vocab modulation

Tokens are clamped into DEFAULT_TRAINING_VOCAB_SIZE = 32768 via _read_token_matrix — a deliberate cap so the model can grow vocab independently of the packed data.

AdamW + clip

AdamW separates weight decay (regularizer on weights) from gradient clipping (post-hoc clamp on the gradient norm). Both are stability seatbelts and serve different purposes.

3.3  Optional resume

start_step = 0
if context.resume is not None:
    start_step = _load_resume_checkpoint(...)

The resume path is paranoid, on purpose:

  1. Trust check via require_trusted_checkpoint — the manifest is the signed metadata. Checkpoint loading is treated as a security boundary.
  2. weights_only=True on torch.load — limits the unpickler to safe tensor types.
  3. Schema-version check on the checkpoint payload.
  4. State-dict compatibility check on model and optimizer.

3.4  The training loop

model.train()
while step < target_step:
    for raw_batch in train_loader:
        if step >= target_step: break
        batch = _to_transition_batch(raw_batch, device=..., action_view=...)

        optimizer.zero_grad(set_to_none=True)
        with _autocast_context(precision, device, runtime):
            outputs = model(batch)
            z_pred_after_swapped = _swapped_action_prediction(model, outputs)
            terms = compute_transition_objective(
                outputs["z_before"], outputs["z_after"], outputs["z_pred_after"],
                config=objective_config,
                z_pred_after_swapped=z_pred_after_swapped,
                action_emb=outputs["action_emb"],
                action_reconstruction=outputs.get("action_reconstruction"),
            )
        terms.total.backward()
        grad_norm = runtime.nn.utils.clip_grad_norm_(model.parameters(), max_norm=...)
        optimizer.step()
        step += 1
        ...
Why while + for?
The pattern is the standard “I want N steps, not N epochs.” When the loader exhausts, the while re-enters and starts a new epoch. The inner break ensures we stop mid-epoch if we hit target_step. max_steps is additional steps, not absolute — important for resume semantics.

The action-swap probe

def _swapped_action_prediction(model, outputs):
    swapped_action = outputs["action_emb"].roll(shifts=1, dims=0)
    return model.predict_after(outputs["z_before"], swapped_action)

We shift the actions by one position in the batch, then re-predict. If the model is actually using the action, the swapped prediction should be worse. If they're equally good, the model is ignoring the action — which usually means it's collapsing onto a z_pred_after = z_before shortcut. This shows up downstream as action_diagnostics/swap_distance_gap in the metrics, and (optionally) as a contrastive loss term.

Hard gate
_validate_no_collapse_smoke raises TrainingRunError if per_dim_variance_max ≤ 0 or embedding_norm_mean ≤ 0. The executor refuses to produce an artifact for a catastrophically-collapsed run. Stricter thresholds live in the eval suite, not here — the executor only catches the smoke.

Two artifacts are always paired:

  • checkpoint.pt — model + optimizer state, plus the compatibility config hash. Opaque pickle.
  • checkpoint.pt.manifest.json — the trust artifact. Plain JSON; inspectable with no torch installed. The resume path refuses to load a checkpoint without a valid manifest.

The training report (reports/torch_training_report.json) is the publication artifact: schema version, run id, full final metrics, collapse report, objective payload, runtime fingerprint. allow_nan=False, sort_keys=True, indent=2 — deterministic JSON, no NaN/Infinity.

04 The Transition Objective

File: codelewm/model/objective.py:154. This is where the science lives. The skeleton: 

prediction_mse = compute_prediction_mse(z_pred_after, z_after)             # ALWAYS
sigreg         = compute_sigreg_loss(stack(z_before, z_after, z_pred_after))  # ALWAYS
total = prediction_mse + sigreg * config.sigreg_weight

if config.enable_retrieval_loss:                total += retrieval_weight * retrieval_loss
if config.enable_action_use_margin:             total += margin_weight    * margin_loss
if config.enable_action_swap_contrastive:       total += swap_weight      * swap_loss
if config.enable_inverse_action_reconstruction: total += inv_weight       * inv_loss

_check_finite(total)
return ObjectiveTerms(...)

Two invariants that shape everything:

  • Two terms are always on: prediction MSE and SIGReg.
  • Optional terms are (flag, weight) pairs. ObjectiveConfig.__post_init__ enforces “enabled ⇒ weight > 0” and “disabled ⇒ weight = 0”. You cannot have an enabled-but-zero term or a disabled-but-nonzero term silently. Discipline against silent misconfiguration.

All optional weights are capped at 1.0. MSE is meant to remain dominant; auxiliary losses modulate, not replace.

4.1  The prediction MSE

def compute_prediction_mse(z_pred_after, z_after):
    return (z_pred_after - z_after).pow(2).mean()
Why MSE, not cosine?
Cosine ignores magnitude. If the model is allowed to choose embedding norms freely, magnitude carries information — predicting both direction and scale of z_after is a stronger constraint. The retrieval loss is the cosine variant; MSE complements it.

This term alone is the JEPA objective in its purest — and most collapsible — form. Everything else exists to make collapse worse than learning the actual task.

4.2  Returned ObjectiveTerms

Every term is logged in two flavors:

FlavorWhat it tells youUse case
Unweighted (e.g. loss/sigreg)Physical signal in natural units“Is the model getting more Gaussian over time?”
Weighted (e.g. loss/sigreg_weighted)Contribution to the actual gradient“Is this term currently driving the optimization?”

4.3  Finite checks (last line of defense)

_check_finite(total, "loss/total")
_check_finite(prediction_mse, "loss/prediction_mse")
_check_finite(sigreg, "loss/sigreg")
if retrieval is not None: _check_finite(retrieval, "loss/retrieval")
...

After all terms are summed, every term is asserted finite. NaN/inf in a single optional term must not silently propagate to total. Paired with _finite_float guards in the executor — defense in depth.

05 SIGReg, In Depth

File: codelewm/model/objective.py:416. This is the most conceptually subtle piece in the whole repo. Worth understanding deeply.

5.1  The problem SIGReg solves

The classic anti-collapse toolkit:

MethodWhat it constrainsLimitation
VICRegPer-dim variance + off-diagonal covarianceOnly second-order moments
Barlow TwinsCross-correlation matrix → identityOnly second-order moments
BYOL / SimSiamArchitectural asymmetry (stop-gradient, EMA target)Implicit, hard to reason about
SIGRegFull distribution matching to isotropic GaussianMore expensive, but stronger

VICReg-style methods can be satisfied by a distribution with the right covariance but a pathological shape — e.g., concentrated on a few delta peaks or a thin manifold. SIGReg tries to make the embedding distribution actually look like an isotropic Gaussian, not just have its first two moments.

5.2  The mathematical idea: characteristic functions

For a random vector X ∈ ℝᵈ and a fixed unit direction u ∈ ℝᵈ, the scalar projection Y = ⟨u, X⟩ has characteristic function:

φ_Y(t) = E[exp(i·t·Y)] = E[cos(t·Y)] + i·E[sin(t·Y)]

For a standard normal scalar:

φ_{N(0,1)}(t) = exp(−t²/2) + 0·i
The trick
If Y is truly standard normal, then E[cos(t·Y)] = exp(−t²/2) and E[sin(t·Y)] = 0 for every t. The characteristic function gives us a per-t certificate of normality. Sample many random unit directions and check this for each → a test of isotropic Gaussianity, because every 1-D projection of an isotropic Gaussian is itself a standard Gaussian.

5.3  Reading the code

projections = torch.randn(d, num_proj, ...) / norm   # num_proj random unit directions in ℝᵈ
t = torch.linspace(0.0, 3.0, knots, ...)              # evaluation points for t
dt = 3.0 / (knots - 1)
weights = full(knots, 2*dt); weights[0] = weights[-1] = dt   # trapezoidal rule
phi = exp(-t² / 2)                                    # target characteristic function
weights = weights * phi                               # weight by Gaussian envelope

x_t = (embeddings @ projections).unsqueeze(-1) * t    # t · ⟨u, X⟩
err = (cos(x_t).mean(dim=1) - phi)² + sin(x_t).mean(dim=1)²
statistic = (err @ weights) * batch_size
return statistic.mean()

What that computes, in math:

SIGReg ≈ (1/num_proj) Σ_u ∫₀³ [(Ê[cos(t·⟨u,X⟩)] − e^{−t²/2})² + Ê[sin(t·⟨u,X⟩)]²] · e^{−t²/2} dt · N

where Ê is the empirical mean over the batch and N is batch size.

Three deliberate choices

  • t ∈ [0, 3]: at t = 3, exp(−t²/2) ≈ 0.011, so the Gaussian-weighted integrand is already tiny — extending past 3 buys very little.
  • Trapezoidal weights: classic numerical quadrature over [0, 3].
  • Multiply by N (batch size): this isn't aesthetic; it's statistical. Under the null (truly isotropic Gaussian), an N · MSE-type statistic has a well-defined limit distribution. So as you increase batch size, the magnitude of SIGReg under perfect Gaussianity stays roughly constant — you don't need to retune sigreg_weight when you change batch size. Many anti-collapse losses get this wrong.

5.4  Applied to all three latent flavors

sigreg_input = stack_objective_embeddings(z_before, z_after, z_pred_after)
# shape: [time=3, batch, latent_dim]

We stack three latents along a new “time” axis and force each slice to be isotropic-Gaussian across the batch. Why all three?

Collapse modeCaught by
z_before collapsedEncoder is a constant function
z_after collapsedEncoder is a constant function (post-edit side)
z_pred_after collapsed (others healthy)Transition head is constant — “ignore the action and output the centroid”

5.5  What SIGReg does to optimization

Three forces the SIGReg gradient applies
  1. Spread the batch. Clustered points → cos(t·Y) empirical mean too close to 1 (all Y values agree) → penalty pushes points apart.
  2. Center the batch. Non-zero batch mean → non-zero sin(t·Y) empirical average (target is 0) → penalty drives the mean to zero.
  3. Match Gaussian tails. Heavy- or light-tailed distributions distort cos/sin averages away from the target curve.

The cumulative effect: push the latent distribution toward a high-entropy, isotropic shape — exactly the opposite of collapse.

06 The Action-Use Probes

SIGReg guards the encoder. The action side needs its own guards: the transition head could still be lazy, copying z_before or ignoring the action's specific content. Three optional losses target three named failure modes.

6.1  Action-use margin — “beat the identity baseline”

def compute_action_use_margin_loss(z_before, z_after, z_pred_after, *, margin):
    target = z_after.detach()
    no_action_delta = z_before.detach() - target          # identity baseline
    pred_delta      = z_pred_after - target
    return torch.relu(pred_dist - no_action_dist + margin).mean()
Intuition
For many edits, the code barely changes, so the trivial “do nothing” baseline (z_pred_after = z_before) already gets a decent MSE. This hinge loss says: the model's prediction must beat the identity baseline by at least margin. Zero only when pred_dist + margin ≤ no_action_dist.

Note the detach() calls. Gradients flow only through z_pred_after. We don't want this loss to teach the encoder to make z_before bad; we want it to teach the predictor to be better than the encoder's no-op fallback.

6.2  Action-swap contrastive — “use the right action”

def compute_action_swap_contrastive_loss(z_after, z_pred_after, z_pred_after_swapped, *, margin):
    positive_dist = (z_pred_after        - z_after.detach()).pow(2).mean(dim=...)
    swapped_dist  = (z_pred_after_swapped - z_after.detach()).pow(2).mean(dim=...)
    return torch.relu(positive_dist - swapped_dist + margin).mean()

The training-time twin of the swap diagnostic. The diagnostic measures the swap gap; this loss trains the gap to be large.

6.3  Margin vs swap — why both?

LossBaselineCatches
Action-use marginIdentity (no action info)Predictor ignores action entirely
Action-swap contrastiveWrong action (some action info)Predictor uses generic action features (length, type), not the right one

A model can pass the margin loss by using some function of the action (e.g., only its length). Swap would still fire because the wrong action has the same length distribution. Together they pin down: “the model is using the specific action semantics, not just any feature of it.”

6.4  Inverse-action reconstruction — dual constraint

def compute_inverse_action_reconstruction_loss(action_reconstruction, action_emb):
    return (action_reconstruction - action_emb.detach()).pow(2).mean()

If the model exposes an inverse head I(z_before, z_after) → action_reconstruction, this loss enforces:

From the two latents alone, you should be able to recover the action that connected them.

It's the dual of the main objective:

Forward(z_before, action) → z_after — the transition head
Inverse(z_before, z_after) → action — the inverse head

If both directions are learnable, the latents are forced to carry enough information about the dynamics to be invertible. Same idea as inverse-dynamics models and Dreamer-family world models.

6.5  Retrieval (InfoNCE) — “beat every wrong target”

def compute_in_batch_retrieval_loss(z_pred_after, z_after, *, temperature):
    scores  = compute_retrieval_score_matrix(z_pred_after, z_after, temperature=temperature)
    targets = torch.arange(scores.size(0), device=scores.device)
    return torch.nn.functional.cross_entropy(scores, targets)

The SimCLR / CLIP-style contrastive loss. L2-normalize, build a (B × B) cosine similarity matrix scaled by 1/τ, treat row i as a classification problem with correct answer j = i, apply softmax + cross-entropy.

What it enforces:

For each example i, the predicted latent z_pred_after[i] should be closer to its own z_after[i] than to any other example's z_after[j].

That's much stronger than MSE alone — MSE cares about absolute distance, retrieval cares about relative ordering within the batch. Collapse catastrophically fails retrieval: identical embeddings give a uniform softmax and loss of log(B).

Why capped at 0.1?
retrieval_weight_cap = 0.10. Retrieval has a known failure mode: it can be satisfied by direction alone, ignoring magnitude. And it's O(B²) memory. So it's a probe, not a driver.

07 Anti-Collapse Toolkit

Time to put it all together. Read this table backwards from the “what collapse mode it kills” column — every optional term targets a specific named failure mode. That maps directly to ablation studies.

Term Always on? What collapse mode it kills
prediction_mse YES None — it's the signal, not a guard.
sigreg YES Encoder/predictor outputs collapsed to a point or low-dim manifold.
retrieval optional Different examples' predictions all live in the same spot.
action_use_margin optional Predictor is identity (ignores action entirely).
action_swap_contrastive optional Predictor uses some action feature but not the right one.
inverse_action_reconstruction optional Latents don't preserve enough info about the dynamics.

7.1  Measurement is separate from training

The training executor only catches the smoke (per_dim_variance_max ≤ 0, embedding_norm_mean ≤ 0). The full audit lives in compute_collapse_report:

MetricWhat it tells you
effective_rankEntropy of the singular value spectrum. Collapsed models have effective rank ≪ latent_dim.
effective_rank_ratioSame, normalized by latent dim.
per_dim_variance_{min,median,max}Dead dims have variance ≈ 0.
pairwise_cosine_meanAll embeddings pointing the same way ≈ 1.
embedding_norm_meanShould be stable.
nearest_neighbor_entropyHow spread out the neighborhood structure is.
The whole anti-collapse posture, in one sentence
Variance and norm being non-zero is necessary but not sufficient for a healthy model. The training executor's job is to produce the metrics, not to adjudicate them. Adjudication lives in the eval suite — where stricter thresholds, downstream probes, and ablation studies live.

7.2  CodeLeWM's bet vs the alternatives

Compare to standard JEPA recipes:

  • I-JEPA / V-JEPA: invariance + EMA target encoder, no explicit anti-collapse term. Rely on architectural asymmetry.
  • VICReg: variance + covariance only. Works but misses higher-order structure.
  • CodeLeWM: MSE + distribution matching (SIGReg) + action-aware probes (margin, swap, inverse).

The author bet that (1) distribution matching is a stronger anti-collapse signal than moment matching, and (2) action-aware losses are essential when transitions are dictated by a controllable input. Both bets are testable hypotheses, which is exactly what the ablation-friendly config supports.

08 Reproducibility Contract

Most of the “extra” code in this repo isn't anti-collapse — it's the reproducibility contract. Worth naming the moving parts.

8.1  Schema versions everywhere

ConstantGuards
DATASET_SCHEMA_VERSIONThe packed HDF5 file format

TORCH_CHECKPOINT_SCHEMA_VERSIONThe executor's .pt payload shape

Every read site checks the version and raises on mismatch. Every write site stamps the version. This is what lets the eval suite, the paper figures, and the leaderboard tooling evolve safely.

8.2  Determinism levers

  • _seed_everything(seed) — Python, NumPy, torch CPU, torch CUDA.
  • DataLoader generator — runtime.Generator().manual_seed(seed) makes shuffling order deterministic.
  • SIGReg seed — sigreg_seed in ObjectiveConfig; the random projections are reproducible.
  • Deterministic JSON — allow_nan=False, sort_keys=True.

8.3  Trust boundary on checkpoints

  • Signed manifest via require_trusted_checkpoint.
  • weights_only=True on torch.load.
  • State-dict compatibility check raises CheckpointCompatibilityError on mismatch.
  • Optimizer state migrated to device via _move_optimizer_state.

8.4  The fail-loud philosophy

Pattern to recognize
Every guard in this codebase prefers raise to warn-and-continue. _finite_float turns NaN/inf into a hard error. _check_finite refuses to backprop NaN. The dataset checks row counts, widths, schema versions. The collapse smoke check refuses to emit an artifact for a broken run. Silent corruption is the worst outcome for a research harness; loud failure is always better than a misleading number on a leaderboard.

If you only remember three things

1. The risk is collapse

Pure MSE on latents has a trivial “constant encoder” minimizer. Every other term in this codebase is a guard or a probe against that.

2. SIGReg is distribution matching

Random projections + characteristic-function matching against N(0,1). Stronger than VICReg-style variance/covariance constraints.

3. Action probes guard the transition head

Margin (beat identity), swap (beat wrong action), inverse (recover action from latents). Each kills a specific named failure mode.
